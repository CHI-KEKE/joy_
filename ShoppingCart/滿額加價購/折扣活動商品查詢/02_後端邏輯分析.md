## 完整查詢流程（以選擇「滿件加價購」為例）

### Step 1｜前端送出的查詢參數

```
PromotionTypeDef       = "CartReachPieceExtraPurchase"
PromotionDiscountTypeDef = "CartReachPieceExtraPurchase"
```

（dropdown value 格式為 `{TypeDef}_{DiscountTypeDef}`，前端 split('_') 後分別送出）

---

### Step 2｜`TransPromotionEngineTypeDef`

```csharp
// 所有 if-else 條件均為舊式組合（TotalQtyV2、TotalPriceV2 等），皆不匹配
// → promotionEngineTypeDef = "CartReachPieceExtraPurchase" (直接傳遞)
```

---

### Step 3｜判斷資料來源：DB vs MongoDB

```csharp
queryFromN1PromotionServiceTypeList = ["AddOnsSalepageExtraPurchase"]
// ↑ 只有商品加價購走 MongoDB，其他全走 DB

isMongoDBPromotion = !empty("CartReachPieceExtraPurchase")
                     && list.Contains("CartReachPieceExtraPurchase")
                   = false  ← 走 DB 路徑
```

---

### Step 4｜`GetSalePageListFilterPromotion`（從 DB 撈活動）

```csharp
var promotionEngineList = DB.GetList(supplierId, shopId)
    .Where(p =>
        p.PromotionEngine_EndDateTime > DateTime.Now   // ✅ 自動過濾已過期
        && p.PromotionEngine_TargetTypeDef == "SalePage")
    .Where(w => w.PromotionEngine_TypeDef == "CartReachPieceExtraPurchase") // ✅ 類型精確過濾
```

> `CartReachPieceExtraPurchase` 活動儲存在 DB 的 `PromotionEngine` table（非 MongoDB）。

## 「全部」選項的流程

```
PromotionTypeDef = ""（空字串）
↓
isMongoDBPromotion = false（promotionEngineTypeDef 是空的）
↓
GetSalePageListFilterPromotion，略過 TypeDef 過濾條件
↓
取出 DB 中所有未過期的 SalePage 活動
（自然包含 CartReachPieceExtraPurchase）✅
```

> ⚠️ 注意：「全部」只涵蓋 DB-based 活動，MongoDB-based 活動（AddOnsSalepageExtraPurchase）不包含。這是現有設計，與本次需求無關。
