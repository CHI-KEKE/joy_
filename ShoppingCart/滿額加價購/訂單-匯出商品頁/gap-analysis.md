# 現狀 vs User Story 需求差距分析

## 需求對照表

| 情境 | User Story 需求 | 現況輸出 | 符合？ |
|---|---|---|---|
| 滿額加價購活動加購品 | 顯示「**滿額加價購**」 | 顯示「購物車滿額加價購」 | ❌ 文字不符 |
| 滿件加價購活動加購品 | 顯示「**滿件加價購**」 | 顯示「購物車滿額加價購」 | ❌ 完全無法區分 |
| 商品加價購子商品 | 維持原有顯示 | 顯示「商品加價購」 | ✅ |
| 購物車滿額加價（舊機制） | 維持原有顯示 | 顯示「購物車滿額加價購」 | ✅ |
| 非加購品 | 維持原有顯示 | 顯示「否」 | ✅ |

## 現況填值邏輯（ScmNmq）

```csharp
// ERP/Backend/BLV2/SalesOrderDataExport/SalesOrderDataExportService.cs

// 判斷條件
var isExtra = order.SalesOrderSlaveIsExtra == "是" || order.SalesOrderSlaveIsExtra == "Yes";

var isAddOnsSalepageExtraPurchase = OrderItemModeHelper.ContainMode(
    order.SalesOrderSlaveItemType,
    SalesOrderSlaveRuleTypeEnum.AddOnsSalepageExtraPurchase);  // ItemType 含 "A"

var isSubItem = OrderItemModeHelper.ContainMode(
    order.SalesOrderSlaveItemType,
    SalesOrderSlaveItemTypeEnum.Sub);  // ItemType 含 "2"

// 填值
if (isAddOnsSalepageExtraPurchase && isSubItem)
    order.SalesOrderSlaveIsExtra = "商品加價購";  // ✅ 正確

if (isExtra)
    order.SalesOrderSlaveIsExtra = "購物車滿額加價購";  // ❌ 滿額/滿件都走這裡
```

## 根本原因分析

```
SalesOrderSlave_IsExtra (BIT)
    ↓
SP 輸出 "是" / "否"
    ↓
ScmNmq 把 "是" → "購物車滿額加價購" (硬碼，無法區分)

真正能區分的資料：
SalesOrderSlavePromotionEngine_TypeDef
    = CartReachPriceExtraPurchase (滿額)
    = CartReachPieceExtraPurchase (滿件)
但此欄位從未被帶到匯出流程中。
```
