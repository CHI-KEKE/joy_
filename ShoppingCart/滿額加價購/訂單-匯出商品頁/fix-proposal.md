# 修改方案（不改 SP）

## 策略

不修改 SP，在 **ScmNmq 應用層** 額外 batch query `SalesOrderSlavePromotionEngine` 取得 TypeDef，再決定顯示文字。

### 原理

```
SP 已輸出 SalesOrderData_SalesOrderSlaveId (已有)
    ↓
過濾 IsExtra = "是" 的明細，收集 SalesOrderSlaveId list
    ↓
一次 batch query：
    SELECT SalesOrderSlaveId, TypeDef
    FROM SalesOrderSlavePromotionEngine
    WHERE SalesOrderSlaveId IN (...)
      AND TypeDef IN ('CartReachPriceExtraPurchase', 'CartReachPieceExtraPurchase')
      AND ValidFlag = 1
    ↓
建立 Dictionary<SalesOrderSlaveId, TypeDef>
    ↓
回填每筆的顯示文字
```

- 每批資料只打 **1 次** DB（IN 查詢），非 N+1
- 非加價購品不會觸發查詢

## 各檔案修改細節

### 1. Repository — 新增查詢 method

```csharp
// SalesOrderDataExportRepository.cs

public Dictionary<long, string> GetCartExtraPurchaseTypeDefs(IEnumerable<long> salesOrderSlaveIds)
{
    const string sql = @"
        SELECT
            SalesOrderSlavePromotionEngine_SalesOrderSlaveId,
            SalesOrderSlavePromotionEngine_TypeDef
        FROM dbo.SalesOrderSlavePromotionEngine WITH (NOLOCK)
        WHERE SalesOrderSlavePromotionEngine_SalesOrderSlaveId IN @SlaveIds
          AND SalesOrderSlavePromotionEngine_TypeDef IN (
              'CartReachPriceExtraPurchase',
              'CartReachPieceExtraPurchase'
          )
          AND SalesOrderSlavePromotionEngine_ValidFlag = 1";

    return _connection
        .Query(sql, new { SlaveIds = salesOrderSlaveIds })
        .ToDictionary(
            r => (long)r.SalesOrderSlavePromotionEngine_SalesOrderSlaveId,
            r => (string)r.SalesOrderSlavePromotionEngine_TypeDef
        );
}
```

### 2. Core Service — 修改填值邏輯

```csharp
// ERP/Backend/BLV2/SalesOrderDataExport/SalesOrderDataExportService.cs

// ── 新增：batch query TypeDef ──────────────────────────────────────
var extraSlaveIds = orders
    .Where(o => o.SalesOrderSlaveIsExtra == "是" || o.SalesOrderSlaveIsExtra == "Yes")
    .Select(o => o.SalesOrderSlaveId)
    .Distinct();

var typeDefMap = extraSlaveIds.Any()
    ? _repository.GetCartExtraPurchaseTypeDefs(extraSlaveIds)
    : new Dictionary<long, string>();
// ───────────────────────────────────────────────────────────────────

foreach (var order in orders)
{
    var isExtra = order.SalesOrderSlaveIsExtra == "是" || order.SalesOrderSlaveIsExtra == "Yes";

    var isAddOnsSalepageExtraPurchase = OrderItemModeHelper.ContainMode(
        order.SalesOrderSlaveItemType,
        SalesOrderSlaveRuleTypeEnum.AddOnsSalepageExtraPurchase);

    var isSubItem = OrderItemModeHelper.ContainMode(
        order.SalesOrderSlaveItemType,
        SalesOrderSlaveItemTypeEnum.Sub);

    if (isAddOnsSalepageExtraPurchase && isSubItem)
    {
        order.SalesOrderSlaveIsExtra = Translation.AddOnsSalepageExtraPurchase; // 商品加價購（不變）
    }

    if (isExtra)
    {
        // ── 修改：依 TypeDef 區分顯示文字 ──
        typeDefMap.TryGetValue(order.SalesOrderSlaveId, out var typeDef);
        order.SalesOrderSlaveIsExtra = typeDef switch
        {
            "CartReachPriceExtraPurchase" => Translation.CartReachPriceExtraPurchase, // 滿額加價購
            "CartReachPieceExtraPurchase" => Translation.CartReachPieceExtraPurchase, // 滿件加價購
            _ => Translation.ExtraPurchaseReachPriceWithAmount                        // fallback 維持原有
        };
    }
}
```

## 效能評估

| 項目 | 說明 |
|---|---|
| 額外 DB 查詢次數 | 每批資料 **1 次**（IN 查詢） |
| 觸發條件 | 僅在有 `IsExtra=1` 的明細時才查詢 |
| 影響範圍 | 僅影響匯出邏輯，不影響其他功能 |
| 風險 | 低，TypeDef 查不到時 fallback 維持原有行為 |

## 驗收情境對應

| 驗收情境 | 修改後預期 |
|---|---|
| 情境一：滿額加價購加購品 | `TypeDef = CartReachPriceExtraPurchase` → 顯示「滿額加價購」✅ |
| 情境二：滿件加價購加購品 | `TypeDef = CartReachPieceExtraPurchase` → 顯示「滿件加價購」✅ |
| 情境三：回歸（其他類型） | 不進 extra 判斷或 fallback → 維持原有 ✅ |
