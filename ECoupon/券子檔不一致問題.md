## 真的主子檔數字不一致??


```sql
USE WebStoreDB
GO
 
-- 填上主檔 Id
DECLARE @ecouponId BIGINT = 515881
 
-- 查詢主檔
SELECT ECoupon_TotalQty,ECoupon_TakenQty,ECoupon_ReturnQty,*
FROM ECoupon WITH (NOLOCK)
WHERE ECoupon_ValidFlag = 1
AND ECoupon_Id = @ecouponId
 
-- 查詢子檔，數字應該跟 ECoupon_TakenQty 一樣，只是差個負號
SELECT COUNT(1) as [子檔數量]
FROM ECouponSlave WITH (NOLOCK)
WHERE ECouponSlave_ValidFlag = 1
AND ECouponSlave_ECouponId = @ecouponId
AND ECouponSlave_IsTake = 1
```



主檔 TakenQty = -2074
子檔 count 數量 =  2075

子檔數量 > 主檔 TakenQty => 依照 sop 說明表示主檔少扣 => 補扣庫存


問題本質：ECoupon 主子檔不一致（主檔少扣）

正常狀態下的關係

對於不預產券（ECoupon_IsPreProduce = 0），正常狀態應滿足：

 ABS(ECoupon_TakenQty + ECoupon_ReturnQty) = 子檔數量 (IsTake=1, ValidFlag=1)

每次用戶領取時：

 - ECouponSlave 新增一筆 IsTake=1 的記錄
 - ECoupon_TakenQty 同步 -1（往負數方向扣）

------------------------------------------------------------------------------------------------------------------------------------

你現在的情況：主檔少扣

 |ECoupon_TakenQty| 絕對值 < 子檔數量

代表 某幾次領取只建了 Slave，但主檔的 TakenQty 沒有對應扣減，導致主檔「少記錄了幾張被領走」。

------------------------------------------------------------------------------------------------------------------------------------

現行作法解析（依最新的 20250509 版本）

整體流程

 輸入多個 ECouponId
      ↓
 查詢主子檔現況（確認差異）
      ↓
 Backup 主檔到 MATempDB
      ↓
 逐筆 LOOP 計算 @Diff 並更新
      ↓
 Verify 確認修正結果

關鍵計算邏輯

 -- 差異量 = 主檔加子檔加起來應等於 0，現在差多少
 SET @Diff = ABS(@ECouponTakenQty + @ECouponReturnQty + @SlaveTakenQty);
 
 -- 修正方式：透過 ReturnQty 來補差
 UPDATE dbo.ECoupon
 SET ECoupon_ReturnQty = ECoupon_ReturnQty + @Diff

為什麼調 ReturnQty 而不是 TakenQty？

┌──────────┬────────────────────┬──────────────────────┐
│ 比較     │ 舊做法（單筆）     │ 新做法（多筆）       │
├──────────┼────────────────────┼──────────────────────┤
│ 調整欄位 │ TakenQty -= 1      │ ReturnQty += @Diff   │
├──────────┼────────────────────┼──────────────────────┤

├──────────┼────────────────────┼──────────────────────┤
│ 語意     │ 補記「有人領走了」 │ 透過歸還量來平衡帳   │
└──────────┴────────────────────┴──────────────────────┘
