# 系統機制

## Quota 機制（by 商店）

同一廠商同時執行的批次作業有上限限制。

| Config Key | 預設值 | 說明 |
|------------|--------|------|
| `BatchUpload.Supplier.JobLimit` | `10` | 最多同時執行的作業數量 |
| `BatchUpload.JobLimit.DelaySeconds` | `120` | 超過上限時，重新排隊等待秒數 |

**判斷邏輯：**

- 撈取該廠商 `BatchUpload_StatusDef = "InProcess"` 的筆數
- 超過上限 → 重新排隊（re-queue），delay 指定秒數後再試

**相關程式碼：**

```csharp
public List<long> GetBatchUploadProcesseIdList(int supplierId)
{
    using (var transactionScope = new TransactionScope(...))
    using (WebStoreDBEntitiesV2 context = ...)
    {
        var list = (from batchUpload in context.BatchUpload.Valids()
                    where batchUpload.BatchUpload_SupplierId == supplierId
                       && batchUpload.BatchUpload_StatusDef == "InProcess"
                    select batchUpload).ToList();

        return list.Select(x => x.BatchUpload_Id).ToList();
    }
}
```

```bash
https://erp.qa.91dev.tw/v2/DynamicReport/List?report=BatchUploadRepository-QueryOrUpdateBatchUpload
```

## SuccessCount 說明

`BatchUpload_TotalCount` / `BatchUpload_SuccessCount` 不是由主流程統一計算。

每個子 Process 執行完成後，各自更新一次計數。需查看各批次類型的具體實作才能確認更新邏輯。

## 上限筆數驗證

每種批次類型可設定單次上傳的最大筆數。

| Config Key | 預設值 |
|------------|--------|
| `BatchUpload.{BatchUploadType}.MaxCount` | `500` |

**程式碼：**

```csharp
$"BatchUpload.{this.GetBatchUploadType()}.MaxCount", "500"
```

在**第一道驗證**階段（`CreateBatchTask`）即進行上限檢查，超過則直接拒絕。

## 短時間重複執行防護（IsBatchTaskExecuted）

子 Task 執行前會檢查是否在短時間內重複執行。

**執行記錄路徑：**

```bash
{BatchUpload.Storage.Floder}\ExecutedTasks\{yyyyMMdd}\{taskId}\{supplierId}\{BatchUpload_Code}
```

| Config Key | 預設值 | 說明 |
|------------|--------|------|
| `BatchUpload.Storage.Floder` | `C:\Temp\UploadData` | 執行記錄根目錄 |
| `BatchUpload.{TypeDef}.TaskExecuted.ExpireSeconds` | `50` 秒 | 重複執行的認定時間窗口 |
| `BatchUpload.ProcessDuplicate.EmailReceivers` | `erichsu@91app.com;reonachao@91app.com` | 重複執行通知 Email |

**判斷邏輯：**

1. 找到執行記錄檔 → 視為可能執行過
2. `最新執行時間 + expireSeconds > 現在` → 視為尚在時間窗口內 → 中斷並發送通知
3. 已超時 → 將舊執行紀錄改名，允許重新執行
