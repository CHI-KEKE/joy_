# 批次錯誤寫入機制

## 涉及的表

| 表 | 用途 |
|----|------|
| `BatchUploadData` | 每個工作單元的執行狀態（ValidateFailed / ProcessFailed） |
| `BatchUploadMessage` | 每筆錯誤的文字說明，可對應到具體 BatchUploadData |

---

## 錯誤的三個來源

### 來源一：InitBatchData（LoadData 期間，最早階段）

解析 Excel 每列時做**基礎資料查核**，例如：查不到 ShopId、查不到 MemberId 等。  
此階段**逐列處理，不受分組影響**，每個查核失敗產生 1 筆 Message 加入記憶體暫存清單。

```csharp
if (shopId 查不到)
{
    BatchUploadMessageEntity msg = this.CreateBatchUploadMessageItem(item, $"查無商店序號：{item.ShopId}");
    this.UploadFailedMessageList.Add(msg);  // 暫存，尚未寫 DB
}
```

> ⚠️ 此階段的 Message **不改變 BatchUploadData 的 StatusDef**，只是記錄警告。

---

### 來源二：DoValidate（主 NMQ，驗證階段）

以 **BatchUploadData（分組後）** 為單位驗證業務規則。  
驗證失敗時，**有幾個 ErrorMessage 就產生幾筆 Message**：

```csharp
foreach (var dataItem in this.BatchUploadDataList)
{
    validationResult = this.Validate(dataItem.DataEntityList);

    if (!validationResult.IsValid)
    {
        // 1. 更新這筆 BatchUploadData 狀態
        dataItem.BatchUploadData.BatchUploadData_StatusDef = "ValidateFailed";

        // 2. 每個錯誤訊息 → 1 筆 Message
        foreach (var errorMessage in validationResult.ErrorMessages)
        {
            this.UploadFailedMessageList.Add(
                this.CreateBatchUploadMessageItem(..., errorMessage.ErrorMessage, dataItem.BatchUploadData_Id)
            );
        }
    }
}
```

**主 NMQ 結束前統一寫入 DB：**
```csharp
// BatchUploadProcess.cs
this.BatchUploadRepositoryService.InsertUploadFailedMessageList(
    BatchUpload_Id,
    this.BatchUploadService.GetUploadFailedMessageList(),
    isBatchInsert);
```

---

### 來源三：DoProcess（子 Task，執行階段）

分兩種情況：

#### 情況 A：業務邏輯判斷失敗（預期錯誤）

業務邏輯本身判斷「這筆不合法」，主動回傳錯誤訊息 List：

```csharp
var batchUploadMessageList = this.BatchCreateBlackListProcess(...);

if (batchUploadMessageList.Count > 0)
{
    // 1. 更新狀態
    dataItem.BatchUploadData.BatchUploadData_StatusDef = "ProcessFailed";

    // 2. 全部加入暫存清單
    this.UploadFailedMessageList.AddRange(batchUploadMessageList);
}
```

Message 筆數由業務邏輯決定，**沒有固定數量**。

#### 情況 B：Exception（非預期錯誤）+ Retry 機制

```csharp
catch (Exception ex)
{
    this.GetException(batchUploadData, dataItem, ex);
}
```

`GetException` 內部有 **Retry 機制**，以 `BatchUploadData_UpdatedTimes` 作為重試計數器：

```
UpdatedTimes < RetryTimes（AppSetting: BatchUpload.{TypeDef}.RetryTimes，預設 5）
  → 只更新 UpdatedDateTime
  → StatusDef 維持 ReadyToProcess（下次 re-queue 仍會撈到，自動重試）
  → 不寫任何 Message

UpdatedTimes >= RetryTimes
  → StatusDef = "ProcessFailed"
  → 固定寫 1 筆 Message：「資料處理異常，請下載檔案後重新執行」
```

**子 Task 每輪結束時統一寫入 DB：**
```csharp
// BatchUploadTaskProcess.cs
this.BatchUploadRepositoryService.InsertUploadFailedMessageList(
    BatchUpload_Id,
    batchUploadService.GetUploadFailedMessageList());
```

## 完整流程時序

```
主 NMQ
  ├─ InitBatchData    → Message 暫存（記憶體）
  ├─ DoValidate       → Message 暫存（記憶體）+ StatusDef = ValidateFailed
  └─ [結束前] InsertUploadFailedMessageList → 寫入 DB（來源一 + 二）

子 Task（每輪）
  ├─ DoProcess → Message 暫存（記憶體）+ StatusDef = ProcessFailed / 維持 ReadyToProcess
  └─ [每輪結束] InsertUploadFailedMessageList → 寫入 DB（來源三）
```

---

## Message 總筆數計算

```
BatchUploadMessage 總筆數
  = InitData 各列查核失敗筆數
  + DoValidate 各分組 × 各 ErrorMessage 數量
  + DoProcess 各分組業務失敗訊息數（業務邏輯自訂）
  + DoProcess Exception 達 Retry 上限的分組數（固定各 1 筆）
```

極端情況：1000 列 Excel，每列有 3 個欄位驗證失敗 → 最多 **3000 筆 Message**。

---

## BatchUploadData_StatusDef 對照

| 狀態 | 代表的錯誤來源 | 是否有對應 Message |
|------|-------------|-----------------|
| `ValidateFailed` | DoValidate 驗證失敗 | ✅ 有（一或多筆） |
| `ProcessFailed` | DoProcess 業務失敗 或 Exception 達上限 | ✅ 有（一或多筆） |
| `ReadyToProcess`（UpdatedTimes > 0） | DoProcess Exception 重試中 | ❌ 無（等重試完成） |

## 相關 DB 查詢

```sql
-- 查某次批次的所有錯誤明細
SELECT
    BatchUploadMessage_BatchUploadDataId,
    BatchUploadMessage_StatusDef,
    BatchUploadMessage_Note,
    BatchUploadMessage_Title
FROM BatchUploadMessage
WHERE BatchUploadMessage_BatchUploadId = {BatchUpload_Id}
ORDER BY BatchUploadMessage_Id;

-- 查仍在重試中的資料（Exception 但尚未達 RetryTimes）
SELECT
    BatchUploadData_Id,
    BatchUploadData_Title,
    BatchUploadData_UpdatedTimes,
    BatchUploadData_UpdatedDateTime
FROM BatchUploadData
WHERE BatchUploadData_BatchUploadId = {BatchUpload_Id}
  AND BatchUploadData_StatusDef = 'ReadyToProcess'
  AND BatchUploadData_UpdatedTimes > 0;
```

## 備註

- `BatchUploadData_UpdatedTimes` 正常情況下記錄更新次數，在 Exception retry 邏輯中**被借用為 retry counter**，查 DB 時需注意語意區分
- `RetryTimes` 對應 AppSetting key：`BatchUpload.{TypeDef}.RetryTimes`，預設 `"5"`
- Message 的 `BatchUploadMessage_StatusDef` 目前固定寫 `ValidateFailed`，即使是 ProcessFailed 階段產生的也是同一個值（設計上的歷史包袱）
