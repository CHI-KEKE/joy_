# 退運費自動退款邏輯（NMQ）

> 來源：`nineyi.scm.nmqv2` — `ThirdPartyRefundRequestService.cs` Line 273

## 自動退運費的條件

```csharp
// Line 273
bool isSalesOrderFeeUnused = isAllCanceled 
    && salesOrderFee != null 
    && salesOrderFee.SalesOrderFee_TradesOrderSlaveId == null;
```

三個條件**全部成立**才會自動退運費：

| 條件 | 欄位 | 說明 |
|------|------|------|
| 所有子單都取消 | `isAllCanceled == true` | 同一訂單的全部 TS 都已取消 |
| 訂單有運費單 | `salesOrderFee != null` | 非免運訂單 |
| 運費單未被使用 | `SalesOrderFee_TradesOrderSlaveId == null` | 未綁定出貨子單（未出貨） |

再加一個判斷（Line 295）：

```csharp
if (hasWaitingToShipment == false || ...) {
    salesOrderFeeFee = salesOrderFee.SalesOrderFee_Fee; // 才真正退運費
}
```

- `shipmentCount == 0`：沒有待出貨子單

---

## SalesOrderFee_TradesOrderSlaveId 何時寫入？

**`ShippingOrderService.cs` Line 1384：**

```csharp
// 出貨單「撿貨/出貨完成」時執行
salesOrderFee.SalesOrderFee_TradesOrderSlaveId =
    shippingOrderSlaveEntity.ShippingOrderSlave_TradesOrderSlaveId;
```

→ **出貨動作（撿貨/出貨完成）後，運費就被「使用」了，之後即使全退也不退運費。**

## 各情境結論

| 情境 | 退運費？ |
|------|---------|
| 全部商品尚未出貨就取消 | ✅ 系統自動退運費 |
| 部分商品已出貨，其餘取消 | ❌ 不退運費（運費已被使用） |
| 全部商品已出貨，事後全退貨 | ❌ 不退運費 |

## 自動退款流程

```bash
消費者申請退貨
    ↓
SMS 建立 CancelRequest
    ↓
NMQ → ThirdPartyCancelOrderProcess
    ↓
PaymentMiddlewareCancelOrderService.DoCancel()
    ↓
確認 CancelOrderSlave = Finish + PaymentRequest = Finish
    ↓
CreateRefundRequestByCancelFlow()
    ↓
ThirdPartyRefundRequestService（判斷 isSalesOrderFeeUnused）
    ↓
建立 RefundRequest（SourceDef = SalesOrderFee）→ 透過 Razer 退款
```

---

## RefundRequest SourceDef 種類

| SourceDef | 說明 |
|-----------|------|
| `ReturnGoodsOrderSlave` | 商品退款 |
| `SalesOrderFee` | 運費退款（自動建立） |
| `RechargeReceipt` | 補收單退款 |
