# SMS 後台手動退運費

> 路徑：`/RefundRequest/ReturnSalesOrderFee`  
> API：`POST /Api/RefundRequest/ReturnSalesOrderFee`

這是一個**補退工具**，用於自動流程沒有退運費（已出貨情境）時，商家手動補退。

---

## 環境連結

```bash

https://sms.qa1.my.91dev.tw/Api/RefundRequest/ReturnSalesOrderFee
```

APIV2：

```bash
POST /Api/RefundRequest/ReturnSalesOrderFee
```

Request 範例：

```json
{
    "Value": "MM260205LA0001"
}
```

## 流程

```bash
SMS 後台頁面 /RefundRequest/ReturnSalesOrderFee
    ↓（輸入 TM 單號）
CheckReturnSalesOrderFee（先檢查條件）
    ↓（通過）
ReturnSalesOrderFee（執行退款）
    ↓
呼叫 SCM API → csp_ReturnSalesOrderFee
```

## CheckReturnSalesOrderFee 檢查條件

**`NineYi.Sms — RefundRequestService.cs` Line 418-471**，三個條件都要通過：

| # | 條件 | 說明 |
|---|------|------|
| 1 | `SalesOrderFee != 0` | 不是免運訂單 |
| 2 | 出貨狀態 = Finish | 至少有一筆已出貨完成（門市取貨 / 超商取貨類**跳過**此檢查） |
| 3 | 不存在 SalesOrderFee 退款單 | 尚未有運費退款單（狀態不是 Cancel / Fail） |

```csharp
// 條件2：部分配送方式跳過出貨完成檢查
// RetailStorePickup, RetailStoreDelivery, 超商取貨, 門市自取 → shippingFinishCheck = false

// 條件3：已有退款單就不能重複退
var refundRequest = _refundRequestRepository.Get(
    RefundRequestSourceDefEnum.SalesOrderFee.ToString(),
    salesOrderFee.SalesOrderFee_Id,
    notContainsStatus); // 排除 Cancel / Fail 狀態

if (refundRequest.Any()) → 擋住，不能退
```

## 與自動退款的差異

| | 自動退款（NMQ） | 手動退款（SMS 後台） |
|-|----------------|-------------------|
| 觸發方式 | 消費者取消 → 全退 → 系統自動 | 商家在後台手動輸入 TM 單號 |
| 使用條件 | `TradesOrderSlaveId == null`（未出貨） | 已出貨（至少一筆 Finish）才符合 |
| 使用情境 | 未出貨的全退 | 出貨後退貨，運費需另外補退給消費者 |
| 商家可選擇不退？ | ❌ 系統自動執行 | ✅ 商家不去操作就不退 |
