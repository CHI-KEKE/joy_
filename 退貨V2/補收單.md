# 補收單（RechargeReceipt）機制

## 是什麼

補收單是商家在退貨時，對消費者合法扣除部分金額的機制。  
例如：退貨運費差、商品損壞折舊、換貨手續費等。

---

## 誰可以建立

**只有商店客服人員**，透過 SMS 後台手動建立。

```bash
入口：POST /api/RechargeReceipt/CreateRechargeReceipt
系統：NineYi.Sms
授權：需要 [Authorize]（商家帳號登入）
消費者：❌ 無法觸發
```

---

## 建立時的驗證規則

**`RechargeReceiptService.cs`：**

```csharp
// 規則一：補收金額不可大於退貨金額
if (entity.Price < entity.RechargeAmount)
    throw new ApplicationException("補收金額不可大於退貨金額");

// 規則二：同一個 TS 只能有一筆補收單
if (IsValidRechargeReceiptExist(entity.TradesOrderSlaveId, entity.ShopId))
    throw new ApplicationException("補收單已建立!");
```

| RechargeTypeDef | 說明 | SMS 列表顯示 |
|----------------|------|------------|
| `OrderSpreads` | 訂單差價（系統自動建） | ❌ 被排除 |

## 補收單如何影響退款金額

補收金額會寫入 `CancelOrderSlave_RechargeReceiptAmount`（負數）。

退款計算公式（**`ThirdPartyRefundRequestService.cs` Line 376**）：

```csharp
decimal amount = (Price × Qty) + Discount + CancelOrderSlave_RechargeReceiptAmount;
// 範例：62 × 1 + 0 + (-5) = 57
```

→ 補收 SGD 5，消費者實際退回 SGD 57（非 62）。

---

## DB 欄位

`CancelOrderSlave` 表（`CancelOrderSlave.sql` Line 47-49）：

```sql
RechargeReceiptId           bigint NULL
RechargeReceiptAmount       decimal NULL  -- 預設 0，負數
TotalPayment (computed)     -- (Qty × Price + TotalDiscount) + RechargeReceiptAmount
```

---

## 補收單是否一定綁 TS1？

❌ 不一定，依 `RechargeReceipt_TradesOrderSlaveCode` 綁定，哪個 TS 有補收單就綁哪個。

---

## 補收單狀態流程

```bash
Created → Finished（完成退款）
        → Void（作廢）
```

---

## 案例：Elemis SG MG260424N00001

| 項目 | 金額 |
|------|------|
| 商品（SGD 62） - 補收單（SGD 5） | SGD 57（RefundRequest 金額） |
| 運費 | SGD 5（獨立 SalesOrderFee RefundRequest） |
| **Razer 實際收到退款** | SGD 57 + SGD 5 = SGD 62 |

> 原始訂單 SGD 67 = 62 + 5 運費  
> 補收單 SGD 5，所以退 SGD 62，差額 SGD 5 由商家保留。  
> **這是預期行為，非打錯金額。**
