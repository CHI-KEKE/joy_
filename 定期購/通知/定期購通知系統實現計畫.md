## 一、整體架構

### 🎯 **三個 Job 架構**

```
定期購通知系統
    │
    ├─ Job #1：RegularCreateOrderNotifyJob ⭐
    │  └─ 時機：D-3（距配送日 3 天前）
    │  └─ 業務含義：為即將執行的 RegularCreateOrderJob 做預告
    │  └─ 通知類型：
    │     ├─ CreditCardOrderNotify（信用卡扣款提醒）
    │     └─ CashOnDeliveryOrderNotify（貨到付款提醒）
    │  └─ 特點：同一個 Job，根據 pay_type 決定通知類型
    │
    ├─ Job #2：RegularOrderNotifyFailedJob
    │  └─ 時機：D-1（距配送日 1 天前）
    │  └─ 業務含義：建單失敗後的错誤通知
    │  └─ 通知類型：
    │     ├─ CreditCardFailedNotify（信用卡失敗通知）
    │     └─ CreateFailedNotify（建單失敗通知）
    │  └─ 特點：分流邏輯，互斥關係
    │
    └─ Job #3：RegularOrderStockEstimateNotifyJob
       └─ 時機：每週一
       └─ 業務含義：為商店提供未來 3 週庫存預估
       └─ 通知類型：StockNotify（庫存預估通知給店家）
       └─ 特點：用不同 API（V2_RegularOrder_EstimatedQtyNotify）
```

---

### 📊 **通知時間軸**

```
配送日期 = D

D-3  ┌─ 【Job #1】RegularCreateOrderNotifyJob ⭐
     │  ├─ 查詢 rgo_pay_type
     │  ├─ if 包含 CreditCardOnce
     │  │  └─ Type = "CreditCardOrderNotify"
     │  │     PayDateTime = D-2（3天後扣款）
     │  └─ else
     │     └─ Type = "CashOnDeliveryOrderNotify"
     │        PayDateTime = D（當天到貨）
     │
     └─ 寫入 notify_queue（為 RegularCreateOrderJob 預告）

D-2  ├─ regular_create_housekeeper Step ③
     │  └─ 建立 rod detail（佔位）
     │     rgo_in_schedule = 1（防重複）

D-1  ├─ regular_create_housekeeper Step ④
     │  └─ 打 SubscriptionOrderAutoGen API
     │
     └─ 【Job #2】RegularOrderNotifyFailedJob
        ├─ 查詢 rgo_create_order_error_code
        ├─ if 包含 'CreditCardBlackList' || 'CreditCardFail'
        │  └─ Type = "CreditCardFailedNotify"
        └─ else
           └─ Type = "CreateFailedNotify"

D+1  └─ regular_create_housekeeper Step ②
        └─ 廢棄過期失敗期

每週一 └─ 【Job #3】RegularOrderStockEstimateNotifyJob
        ├─ 掃描未來 3 週預計出貨訂單
        ├─ 依商店彙整商品預估量
        └─ 寫入 notify_queue（StockNotify）
           用 V2_RegularOrder_EstimatedQtyNotify 發送
```

## 二、三個 Job 詳細說明

### 📍 **Job #1：RegularCreateOrderNotifyJob**

#### **職責**
距配送日 3 天前（即 `RegularCreateOrderJob` 執行前），將「即將建單」的訂單寫入 `notify_queue`，分流為信用卡或貨到付款通知。

#### **觸發條件**
```sql
WHERE rgo_status = 1                          -- 計畫啟用
  AND rgo_next_ship_date < rgo_pause_date     -- 未暫停
  AND DATEDIFF(rgo_next_ship_date, TODAY) = 3 -- 距配送日3天
```

#### **核心邏輯**

```csharp
// RegularCreateOrderNotifyJob.cs
public async Task DoJobAsync(DateOnly today, CancellationToken ct)
{
    // 查詢距配送日 3 天前的所有訂單（即將被 RegularCreateOrderJob 建單）
    var orders = await GetOrdersByDiffNextShipDateAsync(today, diffDays: 3);
    
    foreach (var order in orders)
    {
        // 根據付款方式決定通知類型
        bool isCreditCard = order.PayType?.Contains("CreditCardOnce") ?? false;
        
        string notificationType = isCreditCard 
            ? "CreditCardOrderNotify"
            : "CashOnDeliveryOrderNotify";
        
        // PayDateTime 計算
        DateTime payDateTime = isCreditCard 
            ? order.ShippingDate.AddDays(-2)  // 信用卡：D-2 扣款
            : order.ShippingDate;             // 貨到付款：D 到貨
        
        // 建立統一的 NotifyQueue
        var queue = new NotifyQueue
        {
            NqType = notificationType,
            NqRefShop = order.ShopId,
            NqRefOrder = order.RegularOrderPk,
            NqRefMember = order.VipMemberId,
            NqContent = JsonSerializer.Serialize(new
            {
                VipMemberId = order.VipMemberId,
                Type = notificationType,
                ShippingDateTime = order.ShippingDate,
                PayDateTime = payDateTime,
                ShippingProfileTypeDef = order.ShipType,
                PayProfileTypeDef = order.PayType,
                SalePageTitle = order.ProductName,
                Qty = order.Qty,
                DeliveryPeriod = order.ShipPeriod
            }, JsonOptions),
            NqPriority = 5,
            NqSendLimit = 3,
            NqCreateUser = "RegularCreateOrderNotifyJob",
            NqCreateTime = DateTime.UtcNow.AddHours(8),
            NqSendStatus = 0,
            NqSendedCount = 0
        };
        
        // 防重複：同一訂單同類型只塞一次
        bool exists = await NotifyQueueRepository.ExistsByOrderAndTypeAsync(
            order.RegularOrderPk, notificationType);
        
        if (!exists)
        {
            await NotifyQueueRepository.InsertAsync(queue);
        }
    }
}
```

#### **相關常數**
```csharp
const int NOTIFY_CREATE_ORDER_IN_DAYS = 3;  // D-3（RegularCreateOrderJob 前 3 天）
```

#### **涉及資料表**
- `regular_order`（查詢 pay_type、shipping_date、status）
- `notify_queue`（INSERT 通知佇列）

#### **實現狀態**
- ✅ CreditCardOrderNotify 已實現（RegularOrderCreditCardNotifyJob）
- ⏳ CashOnDeliveryOrderNotify 待合併

### 📍 **Job #2：RegularOrderNotifyFailedJob**

#### **職責**
距配送日 1 天前，查詢打 API 失敗的訂單，分流為信用卡失敗或建單失敗通知。

#### **觸發條件**
```sql
WHERE rgo_status = 1                           -- 計畫啟用
  AND rgo_create_order_error_code <> ''        -- 有錯誤碼
  AND DATEDIFF(rgo_next_ship_date, TODAY) = 1  -- 距配送日1天
```

#### **核心邏輯**

```csharp
foreach (var order in orders)
{
    string errorCode = order.CreateOrderErrorCode;
    
    // 信用卡錯誤 vs 其他錯誤分流
    bool isCreditCardError = errorCode.Contains("CreditCardBlackList") 
                          || errorCode.Contains("CreditCardFail");
    
    string notificationType = isCreditCardError
        ? "CreditCardFailedNotify"
        : "CreateFailedNotify";
    
    var queue = new NotifyQueue
    {
        NqType = notificationType,
        NqRefShop = order.ShopId,
        NqRefOrder = order.RegularOrderPk,
        NqRefMember = order.VipMemberId,
        NqContent = JsonSerializer.Serialize(new
        {
            VipMemberId = order.VipMemberId,
            Type = notificationType,
            ErrorCode = errorCode,
            ShippingDateTime = order.ShippingDate,
            // ... 其他欄位
        }, JsonOptions),
        NqPriority = 5,
        NqSendLimit = 3,
        NqCreateUser = "RegularOrderNotifyFailedJob",
        NqCreateTime = DateTime.UtcNow.AddHours(8),
        NqSendStatus = 0,
        NqSendedCount = 0
    };
    
    // 防重複：同一訂單同類型只塞一次
    bool exists = await NotifyQueueRepository.ExistsByOrderAndTypeAsync(
        order.RegularOrderPk, notificationType);
    
    if (!exists)
    {
        await NotifyQueueRepository.InsertAsync(queue);
    }
}
```

### 📍 **Job #3：RegularOrderStockEstimateNotifyJob**

#### **職責**
每週一，掃描未來 3 週的定期購預計出貨訂單，依商店彙整預估出貨量，為每家商店寫入一筆 `StockNotify`。

#### **觸發條件**
```
時間：每週一
掃描範圍：TODAY + 7 天～ TODAY + 21 天（未來 3 週）
```

#### **核心邏輯**

```csharp
// Step 1：取未來 3 週的出貨訂單
var shippingList = await GetShippingDateRangeAsync(
    startDate: today.AddDays(7),
    endDate: today.AddDays(21)
);

// Step 2：依商店分組，彙整商品預估量
var groupByShop = shippingList
    .GroupBy(x => x.ShopId)
    .ToList();

foreach (var shopGroup in groupByShop)
{
    long shopId = shopGroup.Key;
    
    // 計算該商店未來 3 週預估出貨的商品清單
    var estimatedItems = shopGroup
        .GroupBy(x => new { x.SalePageId, x.ProductName })
        .Select(g => new
        {
            ProductName = g.Key.ProductName,
            EstimatedQty = g.Sum(x => x.Qty)
        })
        .ToList();
    
    // 檢查是否已存在該商店的 StockNotify
    bool exists = await NotifyQueueRepository.ExistsByShopAndTypeAsync(
        shopId, "StockNotify");
    
    if (!exists)
    {
        var queue = new NotifyQueue
        {
            NqType = "StockNotify",
            NqRefShop = shopId,
            NqRefOrder = 0,           // ← 店家層級，非訂單層級
            NqRefMember = 0,          // ← 店家層級，非會員層級
            NqContent = JsonSerializer.Serialize(new
            {
                ShopId = shopId,
                EstimatedDate = DateRange(today + 7 ~ today + 21),
                Items = estimatedItems
            }, JsonOptions),
            NqPriority = 5,
            NqSendLimit = 3,
            NqCreateUser = "RegularOrderStockEstimateNotifyJob",
            NqCreateTime = DateTime.UtcNow.AddHours(8),
            NqSendStatus = 0,
            NqSendedCount = 0
        };
        
        await NotifyQueueRepository.InsertAsync(queue);
    }
}
```

#### **特殊性**
- ⚠️ **不同 API**：由 `notify_queue_housekeeper` 用 `V2_RegularOrder_EstimatedQtyNotify` 發送
- 🔑 **店家通知**：`nq_ref_order=0, nq_ref_member=0`（店家層級）
- 📊 **每商店一筆**：同一商店每週最多一筆，自動去重

#### **涉及資料表**
- `regular_order`（查詢 shipping_date、qty、product）
- `notify_queue`（INSERT 庫存通知佇列）

## 五、核心設計決策

### ✅ **決策 1：Pre-Shipping 用同一個 Job**
- **原因**：兩種通知都在 D-3，業務流程相同，只差 Type 和 PayDateTime
- **優勢**：減少重複代碼，一致的防重複邏輯
- **代價**：Job 內部分支邏輯增加，但可接受

### ✅ **決策 2：Failed 通知獨立 Job**
- **原因**：觸發時機不同（D-1 vs D-3），錯誤碼檢查邏輯獨立
- **優勢**：職責清晰，易於維護
- **代價**：多一個 Job，但簡化了 Pre-Shipping 邏輯

### ✅ **決策 3：Stock Notify 特殊處理**
- **原因**：時機完全不同（週一 vs 日常），API 不同，通知對象不同（店家 vs 消費者）
- **優勢**：完全隔離，不影響其他通知
- **代價**：需要 `notify_queue_housekeeper` 特殊分流

### ✅ **決策 4：防重複邏輯統一**
- **機制**：`NotifyQueueRepository.ExistsByOrderAndTypeAsync(orderId, type)`
- **唯一鍵**：`(nq_ref_order, nq_type)` 對 StockNotify 改為 `(nq_ref_shop, nq_type)`
- **保障**：同一訂單同類型永遠只發送一次

## 七、重要提醒

### ⚠️ **關於 PayDateTime**
- **信用卡**：PayDateTime = ShippingDate - 2 days（扣款日）
- **貨到付款**：PayDateTime = ShippingDate（到貨日）
- 消費者收到通知時，系統會根據此字段推算何時會發生對應事件

### ⚠️ **關於防重複**
- 檢查邏輯必須在每次 INSERT 前執行
- 使用 DB unique constraint 或程式層雙重檢查
- **StockNotify 特殊**：以 `(nq_ref_shop, nq_type)` 為唯一鍵

### ⚠️ **關於 VipMemberId**
- ✅ 確認已修正：`VipMemberId = order.MemberId`（不是 order.MemberId.ToString() 的反向）
- 📍 檢查位置：RegularOrderRepository 的 JOIN member_info 邏輯

### ⚠️ **關於時間常數**
需要在新版 appsettings 中配置：
```json
{
  "RegularOrder": {
    "NotifyPreShippingInDays": 3,
    "NotifyFailedInDays": 1,
    "StockNotifyLookAheadDays": 21
  }
}
```
